# complex-atlas (`inbox/html-generated/complex-atlas.html`)

Изучаю по просьбе автора (письмо 19, 21.10). Инструмент — `proekty/instrumenty/brauzer/atlas.py`: формула и вкладка передаются через хеш, клики по полю ставятся в комплексных координатах, текст панели печатается.
Карта возможностей — по строкам интерфейса (`ext/tmp/atlas-lit.txt`, 471 строка): восемь вкладок, в «анализе» восемь инструментов, в «фракталах» десять множеств, специальные функции от Γ до j(τ).

## Опыты (21.10, 06:xx)

1. **exp(1/z), «точка», z = 0** → «существенная». Верно.
2. **log(1+z), «ряд», z = 0** → коэффициенты 1, −1/2, 1/3, … верны; **радиус сходимости 1.1111 вместо 1**. Причина в коде (строки 5938–5951, 6052–6066): ближайшую особенность ищут только среди *полюсов* (`findZerosPoles(...).poles`), у логарифма полюса нет, поэтому берётся медиана последних пяти отношений |a₍ₖ₋₁₎/aₖ| при 12 членах: 12/11, 11/10, **10/9**, 9/8, 8/7. Для полюса отношение точно геометрическое и оценка точна; для точек ветвления (log, √) она завышена примерно на 1/n. Не ошибка, а смещение метода; честно было бы подписать «≈».
3. **√z, «продолж.»**, петля из восьми точек вокруг 0 → значение в конце −1, «монодромия × −1», «смен листа 1». Верно. (Сначала у меня вышло −1.145+0.474i: мой `atlas.py` кликал мимо, холст шире своего CSS-бокса в 1.552 раза. Ошибка моя, исправлено: клик в 1+i теперь даёт z₀ = 1.000+1.000i.)
4. **Детектор естественной границы, ложная тревога.** Σ z^(2ᵏ), центр 0 → «естественная граница», 100 % направлений. Вывод верный, но «радиус до границы 0.00», а должен быть ≈1. Проверка-противник: **1/(1−z³) с центром 0 → тоже «естественная граница», 100 %, радиус 0.00**. Это рациональная функция с тремя полюсами. Из 0.1+0.05i та же функция → «изолированные особенности», 19 %; 1/(1−z) из 0 → «изолированные», 6 %.
   Причина (строки 5778–5791): радиус у центра автор сам меряет в сдвинутой точке `nud`, с комментарием «чтобы обойти лакунарную симметрию коэффициентов». Но радиальный марш начинается с несдвинутого `z0` (`let p = z0`). В нуле у функций с пропусками в ряду (1/(1−z³): 1, 0, 0, 1, …) нулевые коэффициенты — это шум, деленный на rⁿ, и `_wcRadius` даёт крошечный радиус. Тогда все 120 лучей «заблокированы» на нулевом шаге.
   **Предсказание до опыта:** если марш начинать с `nud`, то 1/(1−z³) станет «изолированными», а лакунарный ряд останется «естественной границей». **Опыт** на копии с одной правкой (`ext/tmp/atlas-nud.html`, `let p = nud`): 1/(1−z³) → «изолированные», 18 %, радиус 0.847; Σ z^(2ᵏ) → «естественная граница», 100 %, радиус 0.795. Подтвердилось.
   Остаётся смещение: радиус до границы 0.80–0.85 вместо 1. Блокировка срабатывает при R < 1.5·probeRR, а probeRR = 5 % полуширины окна, так что недобор порядка 0.2 при этом масштабе. Это свойство метода, не ошибка.
