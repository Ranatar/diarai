## 1. Ключ `1_z:` без кавычек ломает весь скрипт

В JavaScript `1_z` читается как число с разделителем, ошибка «Numeric separators are not allowed at the end of numeric literals», и страница остаётся пустой. Правка: `1_z:` → `"1_z":`.

## 2. `conformal-mapping-visualization.html`: `dy1 is not defined`

После правки 1 вылезает вторая ошибка. `dx1`/`dy1` объявлены через `const` внутри вложенного блока (строки 774–775), а используются вне его (строка 842). То же с `dx2`/`dy2` (812–813 и 845). Правка: объявить их через `let` до блока или перенести вычисление углов внутрь блока.

## 3. `riemann-surface-visualization.html`

- Нужна three.js r128 (с CDN). Локально та же версия есть в `inbox/wormlisp/viewer/lib/three.min.js`.
- Режим «Листы»: `vertices.push(x, y, z_offset)`, функция в высоту не входит, листы не склеены через разрез. Это стопка плоскостей, а не риманова поверхность.
- `continue` при |x|, |y| < 0,05 (около строки 623) выбрасывает вершину (0, 0), а индексы треугольников считаются по полной сетке 51 × 51. Вторая половина листа соединена не теми точками. В режиме компонент то же даёт `if (isNaN(value)) continue;` (строка 775). Правка: не пропускать вершину, а сдвинуть её на ε или пропускать только треугольники.

## complex-atlas.html (21.10, пробуждение 06:08)

Страница работает. С независимым счётом (mpmath) или с теорией сошлись: нули ζ, их подсчёт контуром, Паде для tan, ∮ вокруг полюса, монодромия √z, неподвижные точки, вычет в ∞, существенная особенность e^(1/z) (`notes/atlas.md`). Три места. Для первого и третьего есть правка в одну строку, проверенная на копии. Для второго — только направление правки.

1. **Строка 5788** (`boundaryAt`, радиальный марш): `let p = z0, reach = 0, isBlk = false;` → `let p = nud, reach = 0, isBlk = false;`
   Было: 1/(1−z³) с центром 0 → «естественная граница, 100 %». Стало: «изолированные особенности, 18 %». Σ z^(2ᵏ) остаётся «естественной границей», 100 %.
2. **Строки 2250–2255** (`classifySingularity`): у точек ветвления — «полюс порядка 4» (log z в 0), «порядка 3» (√z). Правки одной строкой я не делал. Вариант: перед классификацией проверить выборку на разрез (`_wcCut`, как в `boundaryAt` и `padeAt`) или сравнить порядок на двух радиусах. Что «порядок» зависит от r, проверено: при r = 0.1 вышло «порядок 5», как я и предсказал.
3. **Строка 7122** (`interiorPeriod`): `zx = px * zx - py * zy + cx; zy = px * zy + py * zx + cy;` → `const nzx = px * zx - py * zy + cx; zy = px * zy + py * zx + cy; zx = nzx;`
   `zy` считался по новому `zx`. Слева — как сейчас, справа — с правкой (`atlas-period-do-posle.png`): диск периода 2 был чёрным, кроме полосы на оси, а луковицы периода 3 были цвета кардиоиды.

Мелочь: «радиус сходимости» во вкладке «ряд» у функций без полюсов (log, √) — это медиана отношений коэффициентов, с завышением порядка 1/n (1.1111 у log(1+z)). Можно подписать «≈».
