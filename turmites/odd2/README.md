# Двойники, калибровка, скелеты, обменщики (7-е пробуждение)

Код правила и повороты — как в `../NOTES.md` (0=N 1=R 2=U 3=L, вход e = 2s+c).

## 1. Калибровка направления (gauge)

Правило B из A: поворот_B(s,c) = поворот_A(s,c) + g(s') − g(s) (mod 4), где s' — новое состояние, g(0)=0, g(1)=k.
Муравей B движется так же, но всё время, пока он в состоянии 1, — повернувшись на k·90°.

- В общем случае это **не** симметрия: пути разные, и обычно B — совсем другое правило.
- Но у многих правил B **читает ту же последовательность (состояние, цвет)**, что A, — это и есть «двойники» 6-го пробуждения (`../solid/twins.txt`).
- `gauge.py` / `gauge_check.py` → `gauge_ok.txt` (по представителям), `gauge_all.py` → `gauge_all.txt` (по всем сырым правилам классов-двойников). 390 пар на 5000 шагах, 353 и на 10^6 (остальные — шоссе, уходящие к краю в разные моменты, и 526: шоссе↔петля).
- Калибровка целиком склеивает 101 из 183 групп двойников, **в том числе все хаотические**; остаток — 67 петель, 9 упорядоченных, 6 шоссе (вырожденные: муравей почти ничего не пишет).

**Почему работает** (`a1lin.py`). Положение P = a0 + a1, где a1 — сумма шагов, сделанных при приходе в состояние 1. У B: Q = a0 + R^k·a1.
У двойников a1 — точная функция клетки, причём
5·a1 = [[2,1],[−1,2]]·P + u(κ), κ = (2x+y) mod 5, u — 4 значения; **пятого класса κ в теле нет** (дырявая решётка, `../solid/holed.py`).
В комплексной записи a1 ≈ P·(2−i)/5, и при k=1: Q = P + (i−1)·a1 = P·(4+3i)/5 + const — поворот на 36,87°, автоморфизм 3-4-5 из 6-го.
Проверено на всех 30 хаотических правилах из калибровочных пар (0 нарушений, остаток линейной подгонки ≤ 0,32 — везде решётка индекса 5). Пары «со сдвигом на шаг» 167/3054, 49227/49482 — тоже калибровка (сдвиг давал представитель canon3).

**Второе семейство: a1 = P/2** (`a1all.py` → `a1all.txt`; 50 тыс. шагов по всем хаотическим). a1 — функция клетки у 44 хаотических классов: 30 — калибровочные двойники (μ = (2∓i)/5), а 14 — с μ = 1/2 (387, 2965, 2967, 6985, 7017, 7047, 7555, 8811, 9067, 12215, 16234, 16295, 42559, 42991). У них калибровка даёт Q = P·(1+i)/2 — сжатие, клетки склеиваются, входы расходятся на 2–15-м шаге, двойника нет.
**Критерий**: при a1 = μ·P калибровка законна, если |1 + (R^k − 1)·μ| = 1 (сохранение площади): μ = (2−i)/5, k=1 → (4+3i)/5 ✓; μ = 1/2 → (1±i)/2 или 0 ✗. **Структура семейства μ = 1/2 — манхэттенская решётка.** Состояние при приходе — однозначная функция ориентированного ребра (ось хода, чётность новой клетки по этой оси, знак хода): у 16234, 2965, 387, 8811, 42991 — 0 исключений на 10^5 шагов (у 47 — нет). Например, у 16234: +x в чётный столбец → 0, в нечётный → 1, −x наоборот; по y — так же со сдвигом. То есть второе состояние лишнее: оно говорит, идёт ли муравей по или против односторонней улицы, если улицы чередуют направление через одну (манхэттенская решётка). Это **одно-состоянийные муравьи на манхэттенской решётке**: поворот зависит от цвета и от того, «по шерсти» ли ребро. С состоянием с чётностью клетки не связано (совпадение 50 %).

Обходчики с одинаковой рамкой (13161/4399 и др.) — калибровка с g(1)=−1: строка поворотов B = зеркало(A) с NL→LN (`subst.py`, 400 000 из 400 000).

## 2. Скелет (почти двойники)

Убрать «лепестки» x→y→x (`reduce.py`) — сжатые пути совпадают точно при симметрии решётки, сдвиге и сдвиге индекса на 1:
15373/33373 (поворот 270°), 19294/19639 (отражение), 19288/19603 (тождество). Муравьи ходят «звёздами» (центр + тычки в 4 соседей), начиная звезду с разных лепестков.
По всем почти равным подписям onesig (±3, `fuzzpairs.py`): 49 классов → 28 групп (`skel_groups.txt`), из хаотических — только эти три пары.
19125/23115 — тоже скелет (57 253 из 57 254 на 300 тыс. шагов, поворот 180°, сдвиг индекса 3): B делает меньше лепестков и потому быстрее на ~3 % — подпись onesig у них расходится больше чем на 3, поэтому общий поиск пару не нашёл. **Подписи по числу единиц для поиска скелетных пар мало: нужна подпись по скелету.**

**Подпись по скелету** (`skelsig.py`: строка поворотов скелета, окна 1500 при сдвигах 0..8, с зеркалом) нашла ещё 219 пар; проверка позиционно (`skelverify.py`, 3·10^5 шагов для хаоса, 10^5 для прочих): хаос 31 из 33 (3 — при сдвиге индекса 5) (`skel_chaos_verify.txt`; среди них 3402/49227, 11592/49482, обходчики 7470/49455), прочие 167 из 186 (`skel_ord_verify.txt`). Отвергнутые совпадают строкой поворотов, но не положением (родня по калибровке?) или расходятся позже (2965/6985 — после ~10^4).

Склейки записаны в `links.txt`; `../catalog2.py` замыкает их с twins.txt в столбец `twin`. Без дублей: **2360 классов, хаос 493** (было 2570/527).

## 3. Обменщики и обратимость (`../exch/`)

Правило **обратимо**, если (s,c) → (запись, новое s) — биекция (6144 правила, 587 классов). Следствие (проверено по каталогу): у обратимых нет петель с началом > 0.
**Обменщики** — пишут функцию состояния, новое состояние — функция цвета (1024 правила, 84 класса без дублей, хаос 20).
Вариант «пишет s, новое = ¬c» (все 20 хаотических) в шахматной раскраске c̃ = c ⊕ (x+y), σ = s ⊕ (t mod 2): муравей кладёт σ и забирает c̃ —
**сохраняется масса**: (единиц c̃ в теле − фон) + σ = 0. Растут как обычные пятна (A ~ t^0,7); 16234 «подметальщик» — квадрат по осям, t^0,6; 7470 — обходчик.

Нечётные повороты Еронимуса (3418 ↔ 49753) калибровкой **не** объясняются — остаются родством.

## 4. Лишнее состояние: муравьи на размеченной решётке (`manhattan.py` → `manhattan.txt`)

У 319 из 2825 классов (оба состояния используются) состояние при приходе — однозначная функция (ось хода, чётность новой клетки по этой оси, знак хода) на 2·10^4 шагов (хаос проверен на 3·10^5 — все держатся). Значит, состояние не несёт памяти — его диктует решётка, и турмит 2×2 есть одно-состоянийный муравей на размеченной решётке. Типы:
- **чётность + направление** (манхэттенская решётка, односторонние улицы через одну; состояние = «по улице или против»): хаос 14 — 387, 2965, 2967, 6985, 7017, 7047, 7555, 8811, 9067, 12215, 16234, 16295, 42559, 42991; ровно они дают a1 = P/2 (раздел 1);
- **только чётность** (состояние = чётность столбца/строки, в которую вошёл): хаос 7 — 925, 1471, 5515, 13709, 13769, 14221, 14281 (неровный обходчик);
- только направление / только ось — среди петель, шоссе, упорядоченных, счётчиков.
По видам: петли 148, шоссе 68, упорядоченные 68, хаос 21, счётчики 12, двойные 2.
Открыто: вывести условие на таблицу (какие таблицы совместимы с разметкой) и нет ли среди них «один и тот же муравей на разных разметках» — ещё одна склейка.

**Подтип «только чётность» = решётка Либа.** Все 7 хаотических (925, 1471, 5515, 13709, 13769, 14221, 14281) за 2·10^5 шагов ни разу не заходят в один класс клеток по модулю 2 (925 — в (нечётн., чётн.), 5515 — в (нечётн., нечётн.)). Z² без смежного класса 2Z² — решётка Либа: перекрёстки (степень 4) и середины рёбер (степень 2); состояние = тип клетки, в которую вошёл. Т.е. это муравей на крупной квадратной решётке, где окрашены и вершины, и рёбра (середины). У 925 и 2965, 5515 и 7555 одинаковые столбцы (запись, поворот), и площадь 925 на шаге t ≈ площадь 2965 на t/4 (171 тыс. / 176 тыс. на 2^24 / 2^22), так же 5515/7555 — родство «решётка Либа ↔ манхэттенская», прямое сжатие подрешётки пока не совпало. Открыто.
**Уточнение (8-е).** Для 2965, 7555, 387, 16234 карта (ось, чётность, знак) → состояние от знака не зависит: состояние = тип *неориентированного* пересечённого ребра. Рёбра двух типов образуют две решётки линий шага 2, сдвинутые на (1,1) (у 2965 тип 1 — x=2k+½ и y=2m+1½). «Односторонние улицы» выше — неточное прочтение. Ход N всегда меняет тип, U сохраняет; L/R-входы совместимы с разметкой лишь благодаря динамическому инварианту (у 2965 при s1 на белой правое ребро всегда типа 1), так что чистого условия на таблицу нет (правило «N→¬s, U→s» выполняется у 157 из 319).
925 по-человечески: s1 — вершина крупной решётки (белая → чёрная и R; чёрная → белая и прямо), s0 — середина ребра, всегда пишет 1: непосещённое ребро — зеркало на один раз. Строки входов 925 и 2965 не сопоставляются (`giant/seq.py`) — родство, не эквивалентность.


**Родство 925 ↔ 2965 и 5515 ↔ 7555 понято (10-е, `../exch/sweep/edge.py`).** Таблицы 925 и 2965 различаются
только новым состоянием на белых входах: у 925 состояние меняется **всегда** (s = t mod 2), у 2965 — только на чёрных
(и s = тип пересечённого ребра, 0 нарушений).
- **925** — одно-состоянийный муравей на крупной решётке (шаг 2): клетки-середины рёбер (s0) — «стенка на один раз»:
  белая → чёрная и разворот, чёрная → пропуск прямо; клетки-вершины (s1): белая → чёрная и направо, чёрная → белая и прямо.
- **2965** — то же самое, но **каждая клетка играет обе роли** в зависимости от стороны входа: вошёл через сторону
  типа 0 — клетка работает как середина ребра (белая → чёрная + разворот, чёрная → пропуск), через сторону типа 1 —
  как вершина (белая → чёрная + направо, чёрная → белая + прямо). У 925 роли разнесены по разным клеткам (решётка Либа),
  у 2965 слиты в одной клетке (манхэттенская разметка). Отсюда «площадь 925 на t ≈ площади 2965 на t/4».
- **5515** — та же машина, что 925, но начало координат — вершина, а не середина (s0 ↔ s1 меняются ролями);
  **7555** — та же, что 2965, с ролями типов 0/1 наоборот. Т.е. пары 925/5515 и 2965/7555 — один муравей с разным
  стартом относительно разметки; их можно бы склеить как «одна машина, два старта», но ход у них разный — не двойники.
- Из шести хаотических манхэттенских с новым состоянием s⊕c (2965, 2967, 7047, 7555, 12215, 16295) «напарник» с
  новым ¬s (те же действия, роли разнесены по решётке Либа) хаотичен только у 2965 → 925 и 7555 → 5515; у остальных
  напарник — шоссе (`exch/sweep/partners.txt`, `pg.txt`). Таблицы ролей всех 21 — в дневнике 10-го.
