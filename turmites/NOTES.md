# Перепись турмитов 2×2

Турмит — муравей на клеточном поле. У него внутреннее состояние (0/1), под ним клетка цвета 0/1. По паре (состояние, цвет) правило говорит: какой цвет записать, куда повернуть (прямо / направо / разворот / налево), в какое состояние перейти. Потом шаг вперёд. Старт: пустое поле, состояние 0.

Мой код правила — 16-битное число: на каждый вход `e = state*2 + color` по 4 бита (`бит0` — цвет, `биты1-2` — поворот 0=N 1=R 2=U 3=L, `бит3` — новое состояние). Муравей Лэнгтона = 99.
Нотация Пегга/Golly (`pegg.py` переводит): 12 цифр, по тройке (цвет, поворот, новое состояние) на с0ц0, с0ц1, с1ц0, с1ц1; повороты 1=N 2=R 4=U 8=L.

Показать людям: **`ZOO.md`** — зоопарк с картинками.

## Механизмы

- **Двоичный счётчик**, правило 3 (одно состояние: на белом — покрасить и направо, на чёрном — стереть и прямо): полоса шириной 2, пары рядов (0,1), (−1,2), (−2,3)… — биты 0, 1, 2…; каждое возвращение в начало = +1 (на шагах 60, 64, 72, 76 … записаны 8, 9, 10, 11 …). Размер +2 за удвоение времени. Бывают +1 и +4; формы — линии, «X» (14317), «+» (33565). **+1**: 3356 = [(0,U,1),(1,N,0),(1,U,1),(0,N,0)] — только «прямо» и «разворот», т.е. муравей живёт на прямой: одномерная машина Тьюринга, счётчик по биту на клетку, растёт в одну сторону. **+4**: 776 — полоса шириной 3 с точками, растёт в обе стороны по 2 клетки на бит (механизм не разобран). `img/counters-detail.png` (моменты 2^8..2^16).
- **Хаотический счётчик** 8827: шумное пятно плотности ~0,52, а растёт логарифмически (+8–10 клеток за удвоение; проверено до 2^30). Сначала я принял его рост за (log t)² — ошибся на шумном начале.
- **Клин** 2863: после ~1,01 млн шагов хаоса строит сплошной расширяющийся треугольник (как рекордсмен Гочева у других). Высота h ∝ √(t − t₀), t₀ ≈ 1,01·10^6 (по h=414 на 1,1M и h=1222 на 1,8M); площадь ≈ h²/4 растёт линейно, ~2 шага на клетку. `img/wedge-2863.png`.
- Хаотические пятна: размер ~ t^0.35–0.4, единиц ~ t^0.7–0.8 (плотность примерно постоянна).
- Упорядоченные: сплошной ромб 16159, квадрат с диагоналями 16921, линии, растущие на клетку за проход (54553).

## Сверка с известным

«Worm Trails» (Пегг 121181121020 = мой 11259): в источниках «попадает в петлю после 4,3 млн шагов»; у меня — петля периода 28 с шага 4 300 340. Лэнгтон: шоссе 104 с шага 9977 (известно ~10 000).
Двоичный счётчик = вант RF у Тёрка (G. Turk, Vants and Turmites, Artificial Life 31(4), 2025, рис. 4): «путь шириной две клетки… зеркальная симметрия при каждом возвращении» — совпадает с моим разбором правила 3. Турмит Фибоначчи (181181121010) у меня — «упорядоченный», a≈0.5, b≈1.0.

## Инструменты

Сборка: `gcc -O2 -o X X.c`; `onset4k`: `gcc -O2 -DN=4096 -o onset4k onset.c`. Бинарники в .gitignore.

- `census FROM TO STEPS` — первая грубая перепись (`out/part*.csv`). Её поиск периода **ненадёжен** (p=1 по трём шагам) — классы из неё не брать.
- `analyze.py` (canon v1, `classes.csv`), `canon2.py` (`CANON2`), `canon3.py` (`CANON3`; нужен `out/traj.txt` = `./traj 8 4008 < out/reps2.txt`, он не в репозитории — 52 МБ).
- `growth MAXLOG < rules` — размер:единицы в моменты 2^8..2^MAXLOG (поле 8192²). Данные: `growth.csv` (через `growth_an.py`), `out/growth[A-Z]*.txt`.
- `onset MAXSTEPS < rules` — полная история, период (до 200000, держится ≥ min(20000, t/3) шагов), начало периодичности. Вывод: `rule steps escaped period dx dy onset`. Чистые данные — только `out/v2/`. Всё, что до исправления окна, переложено в `old/` и `out/old/` — не доверять.
- `onsetr MAXSTEPS < rules` — то же, но с кольцевым буфером на 2^23 шагов (~40 МБ при любой длине прогона): можно гнать до 2^32. Если откат упёрся в начало буфера, onset < 0 («начало не позже |onset|»; так бывает у петель — пересчитать обычным onset). Проверен: 99, 11259, 935, 2974, 8419 совпали. `-DN=4096` для проверки края.
- Проверка края: шоссе с началом > 10^6 пересчитать `onset4k`; у настоящего начало совпадает, у артефакта (фигура ползёт вдоль края поля) — нет.
- `catalog2.py` → `catalog2.csv`; `report.py` → `out/v2/report.txt`; `notes_records.py` — обновить десятку в этом файле.
- `harvest.py` — новые беглецы из `out/growthM*` (ещё не в `deep28.txt`). Цикл: `harvest.py > w.txt; ./onsetr 268435456 < w.txt; ./onsetr4k 268435456 < w.txt` → дописать в `deep28.txt` секциями «# … поле 8192:» / «# поле 4096:» → `catalog2.py`, `report.py`, `notes_records.py`.
- `render RULE STEPS out.pgm`, `sheet.py out.png STEPS rules...`, `zoo.py` (→ `ZOO.md`, `img/zoo/`).

## Уроки

- Соседство на картинке рождает форму («бабочка» = пятно + его зеркало).
- Прежде чем назвать закономерность, проверить на порядок дальше.
- Короткие окна в поиске периода врут. Края поля врут. Проверять сменой размера поля.
- `ps` не видит фоновых процессов — смотреть по росту файлов. Фоновые прогоны пишут в свои файлы.
